# Архитектурный аудит и план трансформации ИТ-ландшафта компании Fast Cargo

Репозиторий содержит комплексное архитектурное решение по трансформации ИТ-инфраструктуры логистического оператора **Fast Cargo** в рамках M&A-интеграции с ритейл-холдингом **«Продукты с душой»**. 

Проект разработан в соответствии с фреймворком корпоративной архитектуры **TOGAF** и методологией **Google SRE**. Цель трансформации — обеспечение стабильной работы ИС при **10-кратном росте операционной нагрузки** (до 500 000 отправлений в сутки) и интеграция целевых сервисов (EDI, IoT-телематика, CRM).

## Структура репозитория и портфолио

Проект разделен на три последовательных пакета работ (директории):

*   **[`/Task1`](./Task1/README.md) — План архитектурной трансформации:** Стратегическое обоснование перевода технических метрик в экономическую эффективность (ROI, TTM, TCO). Анализ разрывов (GAP-анализ) слоев данных, приложений и инфраструктуры по TOGAF. Техническое обоснование промежуточного этама (3 месяца) и сквозная дорожная карта декомпозиции монолита по паттерну Strangler Fig.
*   **[`/Task2`](./Task2/README.md) — Матрица стейкхолдеров и отработка возражений:** Расширенная матрица стейкхолдеров (Stakeholder Matrix) с ранжированием требований по приоритетам бизнес-ценности и безопасности. Системная отработка критических архитектурных, инфраструктурных и ИБ-возражений со стороны профильных департаментов холдинга (ФЗ-152, PCI DSS, 3000 RPS IoT-нагрузка).
*   **[`/Task3`](./Task3/README.md) — Панель KPI эксплуатации и бизнес-заключение:** Спецификация целевых метрик эксплуатации ядра распределенной системы по методологии SRE (соотношение SLA / SLO / SLI) с методами их инженерного замера. Итоговое резюме для Генерального директора, составленное по фреймворку Argument Performance.

## Ключевые архитектурные паттерны и комплаенс

В рамках трансформации легаси-ландшафта (Shared Database SPOF) в целевое состояние (TO-BE) реализованы следующие подходы:
1.  **Database-per-Service:** Ликвидация скрытой связности на уровне данных (Data Coupling) путем изоляции СУБД для каждого микросервиса.
2.  **Event-Driven Architecture (EDA):** Перевод междоменного взаимодействия на асинхронный брокер сообщений **Apache Kafka** для устранения синхронных заторов и HTTP 504 таймаутов на шлюзах.
3.  **CQRS (Command Query Responsibility Segregation):** Полный вынос ресурсоемких SQL-выборок (SELECT/JOIN) аналитики и биллинга, а также высоконагруженного Time-Series потока телематики (**3000 RPS**) в специализированную колоночную СУБД **ClickHouse**. Оптимизация TCO дисковой подсистемы до 5 раз за счет батчевого сохранения.
4.  **Юридический комплаенс и ИБ (ФЗ-152 / PCI DSS):** Физическое обособление персональных данных в контуре **Identity Data Service** с применением UUID-токенизации. Полный вынос платежного контура из периметра ИС Fast Cargo (уровень SAQ A) посредством интеграции безопасного виджета банка-эквайера на фронтенде без обработки PAN-данных карт.

## Методология декомпозиции монолита

Распил транзакционного ядра монолита спроектирован по цепочке бизнес-конвейера: **Телематика/Финансы $\rightarrow$ Заказы $\rightarrow$ Склад $\rightarrow$ Доставка**. 
Для минимизации коммерческих рисков нарушения непрерывности отгрузок внедрен паттерн теневого запуска (**Shadow Routing / Parallel Run**), обеспечивающий верификацию стабильности микросервисов на реальном боевом трафике без риска повреждения данных и без выполнения избыточной работы (Rework) внутри легаси-базы.

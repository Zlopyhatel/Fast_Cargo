# Панель KPI эксплуатации целевой архитектуры Fast Cargo

## 1. Метрики эксплуатации (SLA / SLO / SLI)

| Критерий эффективности | Индикатор качества (SLI) | Целевой уровень (SLO) | Метод и инструмент замера (Физика процессов) |
| :--- | :--- | :--- | :--- |
| **Скорость доставки данных (Analytics Latency)** | Перцентиль `p99` времени доставки бизнес-события от момента фиксации транзакции в СУБД PostgreSQL до записи в колоночную таблицу ClickHouse (DWH). | `p99 Analytics Latency` $\le$ 5 секунд в круглосуточном режиме 24/7/365. | Вычисляется в Grafana как разница (`Timestamp Delta`) между системной меткой времени коммита в PostgreSQL (`created_at`) и временем вставки батча в ClickHouse (`dwh_received_at`). |
| **Доступность ядра системы (High Availability)** | Процент успешных (не-`5xx`) HTTP-ответов интеграционного шлюза API Gateway / BFF при обращении к критическим эндпоинтам транзакционного ядра. | Доступность эндпоинтов микросервисов «Заказы», «Склад» и «Финансы» $\ge$ **99,95%** на скользящем месячном интервале. | Агрегируется в Prometheus на основе логов шлюза API Gateway (FastAPI) по формуле: `(Сумма запросов с кодами != 5xx) / (Общее число запросов) * 100%`. |
| **Пропускная способность (Scalability)** | Количество успешно обработанных и сохраненных транзакций (заказов) и IoT-сообщений в секунду (RPS). | Стабильная обработка пиковой нагрузки $\ge$ **200 RPS** для домена Заказов на API Gateway и $\ge$ **3000 RPS** для потока телематики в Kafka при **0%** утери данных. | Мониторинг метрики `Requests Per Second` на балансировщике API Gateway и метрики `Incoming Messages Rate` в кластере Apache Kafka. Дополнительно контролируется `Consumer Lag` коннектора ClickHouse. |

## 2. Итоговое заключение для Генерального директора Fast Cargo (Argument Performance)

Переход к целевому состоянию позволит компании избежать критических финансовых и операционных рисков, связанных с полной остановкой конвейера отгрузок и потерей контроля над логистической цепочкой «последней мили» из-за каскадных отказов баз данных, а также исключит риски блокировки бизнеса регуляторами и наложения оборотных штрафов за нарушение требований законодательства ФЗ-152 и стандартов безопасности PCI DSS. 

За счёт внедрения событийно-ориентированной микросервисной архитектуры и выделения изолированных технологических контуров для аналитики, телеметрии и платежей, бизнес получит гарантированный коэффициент доступности ядра системы не менее 99,95% в круглосуточном режиме, сокращение времени вывода новых коммерческих сервисов на рынок (TTM) до 1 дня, снижение затрат на хранение данных и содержание ИТ-инфраструктуры до 5 раз, а также доставку сквозной отчетности в холдинг с задержкой менее 2 секунд, что полностью окупит инвестиции в трансформацию ландшафта, гарантирует стабильную работу при росте нагрузок в десять раз, а также создаст надежный фундамент для дальнейшего развития платформы и бесшовной интеграции с новыми контрагентами, в то время как выделенная BI-подсистема позволит контролировать всю операционную деятельность компании в режиме реального времени на основе верифицированных данных с минимальной задержкой.
